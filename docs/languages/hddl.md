# HDDL: bounded hierarchical planning

**Status (2026-09-23):** implemented for finite typed Boolean HDDL with
primitive actions, abstract tasks, methods, and total/partial task-network
orders. Method preconditions/effects use the reference prefix-task compilation.
Nonnegative action costs and `:metric minimize (total-cost)` are preserved.
Object equality/disequality binding `:constraints` are evaluated on substitutions.
Other binding constructs and general numeric fluents remain explicit refusals.

Primary sources are the HDDL paper and grammar, plus the BSD-3-Clause
`pandaPIparser` reference corpus:

- Höller et al., [HDDL: A Language to Describe Hierarchical Planning
  Problems](https://arxiv.org/abs/1911.05499)
- [pandaPIparser](https://github.com/panda-planner-dev/pandaPIparser)

## Source semantic construction

An HDDL problem denotes finite object structures, states, partially ordered task
networks, method-decomposition sequences, and executable primitive
linearizations. Satisfaction is plan existence:

```text
M |= P
iff
there is a decomposition of P's initial task network to a primitive network
and a linear extension executable from init whose final state satisfies goal.
```

The source Institution is `hddlInstitution()`. Its model class and satisfaction
relation are distinct from PDDL: a sequence that reaches the goal is not a
model unless the hierarchy generates it. `sourceSemanticSpec("hddl")` therefore
requires both `PLAN_HORIZON` and `DECOMPOSITION_DEPTH`.

## Translation contract

For bounds `(k,d)`, the frontend constructs
`T=(Phi,A,alpha,beta,h)`:

- `Phi` reuses the PDDL injective mapping from mutable grounded state/action
  coordinates to target Booleans. Tuples that no retained action or method
  event can write reconstruct from the closed initial state; both add and
  delete targets of quantified and conditional effects remain mutable.
- `A` contains administrative one-hot action selection, noop suffix, and noop
  state-preservation axioms.
- `alpha_classical` is the PDDL closed-world initial state, preconditions,
  complete successor-state relation, and goal at the derived execution
  capacity, including method events as described below.
- `alpha_HTN` grounds methods, expands abstract tasks to depth `d`, preserves
  task-network precedence, represents every primitive topological linearization of
  length at most `k`, and relates them to the action-choice coordinates.
- `beta` decodes primitive actions as `plan[t]` and method state events as
  `method[t]`, using the compiled execution index `t`; method events therefore
  leave gaps in primitive-action indices. Padding contributes neither kind of
  event. With a total-cost metric, `h` preserves its exact rational value and
  minimization direction over the admitted bounded plans.

The executable contract is
`hddlToRelationalContract()` with id
`hddl-to-typed-relational-core-v1`. The hierarchy formula belongs to `alpha`,
not `A`: it restricts source solutions rather than target representation.

## Partial-order lowering

Each grounded task network is a DAG. Expanding a compound occurrence substitutes
a method's child DAG. For every parent precedence `u < v`, the encoder connects
each maximal primitive node of the expanded `u` network to each minimal node of
the expanded `v` network. Transitive parent reachability handles empty child
networks. A frontier with a unique topological order uses its fixed sequence.
For an unordered frontier of `n` occurrences, an auxiliary integer position
for each occurrence ranges over `[0,n)`. All positions are distinct; every
precedence edge requires a strictly smaller position; the action choice at
that position has the occurrence's label. Thus the positions are a bijection
onto the execution slots and encode exactly the legal interleavings, without
enumerating up to `n!` orders. Repeated action labels still denote separate
occurrences. Slots after the selected frontier are padding, and scheduling
witnesses do not add source observables or consume a new semantic bound.

Alternative frontiers share one vector of existential occurrence positions.
The vector has enough positions for the largest unordered frontier, with
domain `[0,execution_capacity)` and a single distinctness constraint. A chosen
frontier of length `n` restricts its first `n` positions to `[0,n)` through the
action-placement clauses. Any such partial permutation extends to the unused
positions, so sharing does not couple different alternatives or exclude shorter
frontiers. A fixed-sequence alternative leaves those witnesses unconstrained
apart from the satisfiable common domain/distinctness conditions. Placement
and precedence expressions are cached across alternatives; labels that repeat
within a frontier still refer to distinct occurrence positions.

For short frontiers the disjunction is factored through a prefix trie, with
identical suffixes shared as a DAG. This applies Boolean distributivity to the
original placement/order clauses; it does not permit mixing parts of different
decompositions. Long conjunctions remain flat to avoid deep recursive HIR paths.

A conservative minimum primitive length also rejects impossible initial
networks before enumerating their parameter substitutions. Method events have
length zero for this check. Source schemas are validated even when no frontier
fits the bounds.

This is stronger than concatenating method bodies. The official `interleaving`
fixture requires actions from two ordered method bodies to interleave; it is SAT
at plan horizon 4 and UNSAT at horizon 3.

## Correctness statement

For the accepted fragment and fixed bounds:

```text
N |= T[k,d](P)  iff  beta(N) is an HDDL plan of P
                         with length <= k and decomposition depth <= d.
```

Thus the bounded construction is sound and complete relative to `(k,d)`. It is
a global under-approximation because deeper or longer source plans may exist:

```text
SAT(T[k,d](P))  =>  SAT(P)
UNSAT(T[k,d](P)) does not imply UNSAT(P).
```

Both bounds are retained by `Fidelity::meet`; neither is reported as
`BMC_DEPTH`. An optimum within these bounds need not be an unbounded optimum;
the report retains `preserves_optimum=false` for the bounded construction.

## Accepted and refused constructs

Accepted:

- finite object types, subtypes, constants, and problem objects;
- Boolean PDDL action conditions/effects supported by the shared PDDL adapter;
- declared primitive and abstract task signatures with static type checking;
- `:subtasks`, `:tasks`, `:ordered-subtasks`, and `:ordered-tasks`;
- labelled partial-order constraints `(< before after)`;
- recursive methods under an explicit decomposition-depth bound;
- optional goals, empty or omitted method task networks, and empty methods;
- method `:precondition`/`:effect` with the declared extension or recorded lenience;
- deterministic nonnegative action costs using the [PDDL cost fragment](pddl.md);
- legacy `:hierachie` as used by the reference parser corpus.

Refused rather than erased:

- nonempty abstract-task preconditions or effects;
- binding `:constraints` other than conjunctions of object equalities/disequalities;
- general numeric, temporal, and policy extensions not handled by PDDL;
- undeclared tasks, parameters, constants, type mismatches, and cyclic orders;
- missing companion problem or either semantic bound.

## `:requirements` strictness, and the option that relaxes it

`ipc_compatibility=true` (also `1`; default `false`) selects the published IPC
HDDL dialect. It includes `lenient_requirements`, introduces types named only
as parents in `:types`, and pairs the explicitly supplied domain/problem files
even when their domain-name labels differ. It also treats a problem object
repeating a domain constant with exactly the same name and type as the same
object, matching the reference parser's set insertion. Conflicting types still
fail. Repeated type declarations retain every parent edge (multiple
inheritance), including transitive diamond hierarchies. Repeated identical
edges are idempotent; cycles through any parent are rejected. The shared
classical encoder uses the same type DAG for grounding and schema validation.

In this dialect, a method variable is restricted to the intersection of its
declared type and the argument types required by its head and every subtask.
Initial task-network variables use the same rule. For example, a parameter
declared `part` and used in an `engine` argument ranges only over engines;
binding it to a different part does not produce a method instance. When
requirements are incomparable, a generated intersection sort retains all
common descendants. An empty intersection produces no substitutions. These
restrictions are recorded in the translation report and passed to generated
method-state action signatures. They do not repair incompatible constants or
disable the classical action/formula type checker. Strict mode continues to
require the declared variable type to be a subtype at every call site.

It does not find substitute files.
Each introduced type and changed label is recorded in diagnostics and the
translation report as `ipc-hddl-compatibility`; fidelity is relative to this
selected dialect. Unknown types not mentioned by type declarations, actual
type cycles, incompatible constant arguments, and undeclared symbols still fail.
Input files are never rewritten.

This follows the reference parser at revision
[`88c0995`](https://github.com/panda-planner-dev/pandaPIparser/tree/88c0995c72c5ce2685e9546ec153a3545977ed81):
[`hddl.y`](https://github.com/panda-planner-dev/pandaPIparser/blob/88c0995c72c5ce2685e9546ec153a3545977ed81/src/hddl.y)
introduces parent sorts and consumes domain labels without comparing them;
[`sortexpansion.cpp`](https://github.com/panda-planner-dev/pandaPIparser/blob/88c0995c72c5ce2685e9546ec153a3545977ed81/src/sortexpansion.cpp)
propagates subtype members to their parents. Leading typing separators such as
`?heading -HeadingCondition` are tokenized separately in both modes, matching
the reference lexer. Internal name hyphens are preserved.

When forwarding to PDDL, every generated type/parameter annotation includes
its explicit type, including `- object`. Omitting that annotation before a
subsequent non-root annotation changes the grouping of the typed list and is
not a semantics-preserving shortening.

Before grounding method-local parameters, a memoized lower bound computes the
minimum primitive length possible within the remaining decomposition depth.
It ignores bindings and state conditions, so it may underestimate but cannot
overestimate an actual bounded plan's length. Branches whose lower bound
exceeds the source horizon are skipped. Generated method state events have
zero primitive length. Ground-method caches include remaining depth because
the surviving alternatives depend on that depth. All source schema validation
still runs, including unreachable methods/actions.

Mandatory positive method conditions on predicates that no primitive or method
effect can add are joined against the initial relation before remaining local
parameters are enumerated. Such relations can stay constant or lose tuples;
any tuple true when a method executes must therefore have been initially true.
Conditional and quantified positive effects both disable this restriction.
The join respects head arguments, repeated variables, constants and parameter
types. It does not descend through disjunction, negation, implication or
quantifiers. The original method state event still checks its full condition
at execution, so deletions can invalidate an initially admitted candidate.
All classical schemas and initial facts are validated even when joins admit
no frontier. Consumed grounding caches are released before classical lowering.

The same necessary conditions are propagated from each direct primitive
subtask into its enclosing method, substituting the action's formal parameters
with the task call's actual arguments. Every admitted decomposition executes
that primitive occurrence, so a required tuple in a never-added relation must
be initially present regardless of the occurrence's eventual execution time.
This also restricts wrapper methods without their own preconditions. The
action's full execution-time condition remains in the transition encoding.

Method and initial-network `:constraints` accept `(= a b)`, `(not (= a b))`,
and conjunctions of these. Terms are declared parameters or object constants.
All terms are validated even in unreachable methods. Constraints filter ground
substitutions before task expansion and before generated method state events;
an impossible restriction removes that alternative, not a planning-state
assertion. Initial-network restrictions similarly filter its parameter bindings.

The IPC requirement `:method-preconditions` licenses nonempty method
preconditions. It does **not** license method effects; those still require
`:htn-method-pre-eff`. Both requirements are recognized independently of section
order and consumed by the HDDL frontend before invoking the classical PDDL
adapter. This follows the [IPC HDDL addendum](https://ipc2020.hierarchical-task.net/data/hddl.pdf),
whose language is also used by [IPC 2023](https://ipc2023-htn.github.io/#hddl-fragment).

A `:requirements` list declares which fragment of the language a file is written in, and a
conforming planner may reject constructs outside it — so the default is strict and an
undeclared construct is `E_PARSE` naming the requirement to add.

The corpus instruments explicitly use `lenient_requirements=1`: the source
fixtures omit requirements licensing some of their constructs. Every relaxed
requirement, including `:htn-method-pre-eff`, is recorded in an encoding choice.
This changes accepted files, not the interpretation of an accepted construct.

### Method state events

The [reference compiler's `parsed_method_to_data_structures`](https://github.com/panda-planner-dev/pandaPIparser/blob/master/src/domain.cpp)
creates a primitive task with the method's precondition and effects, ordered
before every original subtask. The frontend implements this construction.
Conditions are evaluated when the method event executes; other unordered
branches may execute first. Conditional effects read the old state and update
it simultaneously under the same rules as primitive PDDL actions.

The event is retained even when the method has no subtasks. Generated task
names cannot collide with source actions, and source task calls are validated
before any generated declarations become visible. Only method parameters used
in its state formulas are carried by the event; the full method substitution
still determines the task network. The method event is projected as
`(method METHOD ARG...)`, distinct from a source primitive action.

`PLAN_HORIZON=k` continues to count source primitive actions. Method events do
not consume it. Enumerating all frontiers within `(k,d)` yields their maximum
compiled length; this derived length sizes the classical transition encoding.
It is not a third approximation bound. Thus a method-effects-only plan may
have zero primitive actions and several state-changing events. The unchanged
upstream `method-effect` example executes `{p} -> {q} -> {r} -> {r}` through
three such events and satisfies its goal with `k=0,d=2`.

`minecraft-costs` additionally needs numeric cost semantics and scalable method
instantiation. Those remain open; adding method state events alone does not
close that sample.

## Verification

`test/languages/test_hddl.cpp` checks both bounds, contract validation, model
projection, hierarchy-only action admission, empty decompositions, official
partial-order interleaving, and refusal paths. `test/python/test_hddl_method_state.py`
checks state-event ordering, dynamic precondition timing, independent source
progression, zero primitive-step bounds, name capture and malformed fields.
Z3 audits establish:

- local one-hop transport: SAT;
- the same goal reachable only through an action absent from every method:
  UNSAT;
- official `interleaving`: SAT at `(k=4,d=1)` and UNSAT at `(k=3,d=1)`;
- official empty method: SAT at `(k=0,d=1)`.
