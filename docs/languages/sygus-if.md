## Source Semantics

A SyGuS problem asks for a function generated by a grammar, not merely an
interpretation of an unrestricted SMT function:

```text
exists f in L(G). forall declared inputs x. constraints(f, x)
```

The grammar and universal closure are semantic data. Dropping either changes the
solution set. A source solution is a `define-fun`, so model projection must return
that definition rather than internal SMT selector variables. See the
[SyGuS-IF 2.1 standard](https://sygus-org.github.io/assets/pdf/SyGuS-IF_2.1.pdf)
and the [official language page](https://sygus-org.github.io/language/).

## Semantic Construction

Omitting both grammar options selects `grammar_mode=unbounded`. Grammar
nonterminals become inductive datatypes, and mutually recursive evaluators
interpret finite derivation trees. There is no depth bound on those trees. A
single `(Constant Sort)` production uses a typed value witness directly; other
grammars retain their production structure and a source-term renderer. Witness
projection checks the selected production and reconstructs source syntax,
including original helper names. Target-only closure arguments never enter the
projected source definition. Each synthesized function has its own tree or typed
value witness. Multiple functions share one universally closed specification;
the invariant entrance expands to the same three obligations described below.
Fixed wrapper equations keep each function independent of captured universal
inputs. Ordinary helper definitions retain their bodies through HIR, while AST
evaluators retain their explicit recursive groups in the emitted SMT module.
Repeated nonterminal occurrences inside a nested production receive independent
AST fields, just as direct sibling occurrences do. Shared function lowering also
retains acyclic evaluator/renderer calls when their transitive macro expansion
would become large; this does not bound the grammar's derivation trees.

For a requested `grammar_depth=d`, the frontend represents the well-sorted terms
derivable from each explicit grammar's start nonterminal within depth `d`. Small
grammars use explicit enumeration; large production products use a compact
derivation circuit with an integer selector at each branching occurrence. Repeated
nonterminal occurrences choose independently, while each choice stays fixed across
all universally quantified inputs. Integer
`(Constant Int)` productions carry symbolic nonnegative numeral witnesses, so
this representation does not impose an arbitrary maximum constant. Negative
integers are constructed by unary minus. Each occurrence has its own witness,
shared across every use of that candidate in the specification. It then constructs:

- `Phi`: Boolean candidate selectors or integer production selectors mapped to
  target variables;
- `A_Sigma`: exactly-one constraints or production-index ranges, plus numeral bounds;
- `alpha`: each selector guards the universally closed source constraints after
  substituting the corresponding candidate body;
- `beta`: the selected candidate is decoded to a source-level `define-fun`,
  substituting its typed numeral witnesses with concrete model values;
- `h`: identity, because the accepted fragment has no optimization objective.

For one synthesized function whose candidates do not capture universal variables,
each candidate selector guards the universally closed specification after
substituting that candidate body. For multiple
functions, the target uses independent exactly-one selector groups and
selector-defined wrappers, then asserts the rewritten source constraints jointly
under one universal closure. This keeps cross-function constraints coupled
without enumerating the candidate Cartesian product. Every wrapper is constrained
to its selector-controlled candidate body; it is not an unconstrained UF. The
target represents one joint existential choice of all definitions and their typed
holes, followed by the original universal specification.

The compact path encodes productions as shared term templates instead of
materializing every combination of child candidates. Its projection traverses the
selected derivation, preserving source helper names and independently chosen child
occurrences. Inactive branches need no model assignments. Fixed single-production
nodes still validate their typed constant bindings. This changes storage and
encoding size; it does not increase the requested grammar depth or make bounded
UNSAT conclusive for unrestricted synthesis.

If a well-sorted grammar has no derivation at the requested depth, the target
contains `assert false` and the report records `empty-bounded-grammar` with that
depth restriction. No candidate or definition witness is invented. Grammar
productions, helper definitions and source constraints are still validated,
including those belonging to other synthesized functions; an empty search space
does not turn malformed source into an accepted model.

Helpers capture preceding `declare-var` symbols through explicit parameters,
including transitive dependencies, while respecting parameter and let shadowing.
If a single-function candidate captures a universal, it also uses a wrapper
equation: one fixed synthesized function must satisfy the equation for every
universal input. Direct substitution would otherwise allow a nullary function
to vary with a source input. A helper may reference only globals declared before
its definition.

The multi-function path accepts both bare references and parenthesized zero-argument
calls to nullary synthesized functions. It emits their SMT constant symbols as
bare terms. Renamed nullary helpers receive the same normalization. Arity and
lexical binding control this rewrite; shadowed names retain their meaning and
calls with an incorrect number of arguments remain errors.

Explicit bit-vector grammars use their declared widths throughout. A
`(Constant (_ BitVec W))` occurrence has a bit-vector witness of width `W`;
projection validates that width and substitutes a bit-vector literal into the
source definition. Arithmetic, indexed extraction and extensions follow
[SMT-LIB fixed-size bit-vector semantics](https://smt-lib.org/theories-FixedSizeBitVectors.shtml),
including modular arithmetic and numeral interpretation. These witnesses do
not receive the nonnegative-Int bounds used for integer constants.
The older competition spelling `(BitVec W)` is accepted in source sort
positions and normalized to `(_ BitVec W)` for SMT output. Legacy signed integer tokens such as `-1`
are normalized to unary negation in grammar terminals, helper expressions and
constraints, as described in section1.1.1 of the standard. Declared symbols
retain their scoped identity; normalization adds no nonterminal unfolding. Previously declared
nonrecursive helpers can occur in grammar productions with checked argument
and result sorts; helpers declared after synthesis are not grammar terminals.

For omitted `BV` grammars, finite enumeration supports the SyGuS-IF 2.1 reference
grammar B.3 fixed-width operators, core equality and Boolean connectives, plus the
common fixed-width extensions listed in the implementation. This is only an
operator fragment of the standard's unrestricted no-grammar meaning (“any term of
the appropriate sort in the output logic”): implicit grammars omit polymorphic
`concat`/`extract` and other terms outside that fragment. Explicit grammars can
use supported `concat`, indexed `extract`, and extensions with width checks. The
report rationale identifies this additional fragment restriction separately
from `grammar_depth`.

String literals preserve SMT-LIB doubled quotes and Unicode escapes. Quoted
identifiers retain their scoped identity, including empty names and whitespace;
literal text is never treated as an identifier during substitution or closure.
In SLIA inputs, the legacy aliases `int.to.str` and `str.to.int` normalize to
`str.from_int` and `str.to_int` in target terms. Original grammar spellings remain
in projected definitions. Source-legal helper names that collide with target
legacy aliases are renamed without changing their meaning. Explicit String
grammars support concrete literals and, in unbounded mode, `(Constant String)`
witnesses. Omitted SLIA grammars remain unsupported.
See the [SMT-LIB String theory](https://smt-lib.org/theories-UnicodeStrings.shtml)
and [lexical syntax](https://smt-lib.org/papers/smt-lib-reference-v2.6-r2024-09-20.pdf).

## Fidelity

Unbounded mode is an exact reduction for the accepted grammar fragment: finite
datatype values represent precisely finite source derivations. Solver `unknown`
or a timeout does not establish either satisfiability or unsatisfiability.

Depth-bounded mode is a **sound under-approximation** of unrestricted grammar synthesis:

```text
target SAT  =>  the projected definition is a valid source solution
target UNSAT  =>  no solution exists at or below grammar depth d
```

Depth-bounded mode is not complete for the full grammar. Its report records
`GRAMMAR_RESTRICTION=d`; no implicit depth is selected. For omitted BV grammars,
the rationale also names the supported operator fragment. `grammar_depth` bounds
grammar derivations, not input values: source constraints remain universally
quantified.

## Supported Fragment

- one or more Int/Bool/BitVec/String `synth-fun` commands, each with a legacy grouped five-item grammar, a modern
  six-item grammar, or a four-item declaration using the LIA/NIA default grammar;
- one Bool `synth-inv`, with an explicit grammar, a LIA/NIA default grammar, or
  the Bool-only SAT default grammar;
- typed parameters, nonterminals, literals, `(Variable Sort)`, `(Constant Int)`,
  `(Constant Bool)`, `(Constant (_ BitVec W))`, and supported Boolean/integer/
  bit-vector productions; implicit BV grammars cover only the fragment described
  above;
- explicit String grammars with String literals/parameters, `str.++`, `str.at`,
  `str.substr`, `str.replace`, `str.len`, `str.indexof`, `str.contains`,
  `str.prefixof`, `str.suffixof`, `str.to_int`, and `str.from_int`;
- nonrecursive `define-fun` helpers, including helpers that call previously
  declared synthesized functions, with scoped parameter substitution;
- `declare-var`, `declare-primed-var`, `constraint`, `inv-constraint`, and
  `check-synth`;
- finite grammar-depth enumeration with strict sort checking.

The frontend refuses synth-function calls inside grammar productions, including
recursive and forward references; these call graphs are outside this encoding.
Default grammars outside LIA/NIA, the Bool-only SAT case, and the documented BV
fragment are rejected. Assumptions/oracles, weights, unsupported sorts or
operators, and malformed or nonproductive grammar references are also rejected.
Helpers must not have recursive or forward dependencies. The SyGuS-COMP'15 invariant extension is supported for
one `synth-inv`: `declare-primed-var x S` declares `x` and `x!`, and each
`inv-constraint inv pre trans post` is elaborated to universally quantified
initiation (`pre => inv`), consecution (`inv and trans => inv'`), and safety
(`inv => post`) obligations. The invariant parameters and pre/post signatures
must match by position and sort; the transition signature must contain current
and next state arguments in that order. A bounded candidate must satisfy all
three obligations before beta returns its Boolean `define-fun`; unbounded mode
uses the same obligations with an unrestricted finite grammar tree.

SyGuS-IF 2.1 removed `declare-primed-var` and the invariant commands. This
invariant support follows the earlier SyGuS-COMP'15 extension described in the
[original invariant syntax proposal](https://sygus-org.github.io/assets/pdf/SyGuS-IF_2015.pdf).

## Usage And Validation

```python
import somtparser as sp

result = sp.translate("languages/sygus/instances/ok/max2.sl",
                    language="sygus", profile="bmc",
                    options={"grammar_depth": "2"})
assert result.exit_code == 0, result.diagnostics
```

Tests pin universal closure, depth-one incompleteness, `(Variable Sort)`, target
parsing, and `beta` reconstruction. The reference `max2.sl` is also checked with
cvc5, whose synthesized body occurs among the depth-two candidates. Independent
Z3 checks additionally cover arbitrary constant 17, shared and independent
constant occurrences, negative numeral construction, nonlinear products, helper
semantics and all 16 assignments of a four-selector encoding. Projection tests
reparse instantiated definitions, including negative numerals and quoted-symbol
aliases. These checks support the implemented fragment; full competition
coverage is measured separately with all 2,854 original SyGuS-Comp 2019 inputs.

Helper names are resolved in the declared source logic. A legal source helper
that conflicts with a reserved name in the broader target logic (for example,
`store` in a BV input) receives a fresh target name. Calls respect parameter,
quantifier and simultaneous-let scope, while projected source definitions keep
the original helper name. A source builtin cannot be redefined, including in a
helper that depends on the synthesized function. Name validation explicitly
covers the core grammar keywords, the BV operator and overflow `NODE_KIND`
ranges, and the currently listed LIA/NIA arithmetic operators. It does not claim
complete builtin-name validation for every SMT-LIB source logic; other logics
use the conservative target-reserved-name fallback.
