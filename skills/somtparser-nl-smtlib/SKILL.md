Produce translation artifacts, not solver answers. Default to noninteractive
operation. Preserve the original source and caller context throughout; report
unresolved interpretations as diagnostics. Deterministic scripts own generation
and checking of the candidate; LLM interpretation is not guaranteed deterministic.

## 1. Choose a route; discover resources

Honor the caller's route; default to `hir` if unspecified:

- `hir`: typed HIR JSON, native CP constructors and shared lowering.
- `smtlib2`: SMT-LIB in the formal candidate envelope.
- `hybrid`: HIR owns declarations/domains/objectives; linked Boolean SMT terms
  extend hard constraints through the same symbol interface.

Read [routes](references/routes.md) only when choosing between routes. Never
switch silently during evaluation. Direct SMT can still use HIR internally;
these routes distinguish the representation generated by the model.

**Use progressive disclosure for the whole package**, including semantics,
macros, templates, dialects and repair guidance. Do not concatenate all files or
the full constructor catalog into the first model call. Capture the live request
locally, then expose only its directory to resource selection:

```sh
python scripts/ir2smt.py --source problem.txt --route hir --request > request.json
python scripts/capability_pack.py index --route hir --request request.json
python scripts/capability_pack.py read --route hir --request request.json --ids arithmetic bool domain.linear template
```

Use the actual route in all commands; optional `--context context.json` supplies
fixed string-to-string conventions. Commands run on the caller's designated
host. They contact neither a model API nor a solver. `read` returns the selected
request view and provenance. Only `core` loads implicitly, including one small
complete example of the selected route's wire format. Missing resources
mean **not yet read**, not unsupported by the compiler.

## 2. Select, read, then generate

Inventory the source's domains, units, clauses, data, objectives and observables.
Choose resources from the returned IDs, inspect them, and only then construct a
candidate. Read more when an unfamiliar construct or diagnostic requires it.
Do not solve the problem in order to translate it.

| Need | Resource IDs / reading |
|---|---|
| Source interpretation | `semantics.core`, `logic`; [semantics](references/semantics.md) |
| Arithmetic and objectives | `arithmetic`, `omt`, `domain.linear` |
| Scheduling/finite constraints | `domain.cp`, the required `cp.*` APIs, `arrays`/`folds` as needed |
| Predicates and quantification | `domain.fol`, `uf`, `quantifiers` |
| Reusable encodings | `macros`; [macro library](references/macro-library.md) |
| Generator structure and dialect | `template`, the requested `dialect.*` |
| Exact candidate shape | `protocol.candidates`; [candidate examples](references/provider-candidates.md) |
| Construction feedback | `repair`; [repair rules](references/repair.md) |

For an API model without filesystem tools, the caller can inject its transport
into `scripts/progressive_provider.py`. It materializes the same resources over
multiple model calls. The [progressive protocol](references/progressive-protocol.md)
specifies lookup/candidate actions, source retention and shared call accounting.
An agent with filesystem access may execute the index/read scripts directly;
it need not perform a redundant planning call when its resource needs are clear.

Preserve source requirements when narrowing documentation. Do not invent bounds,
nonnegativity, integrality, unique names or symmetry breaking. Values to find and
multiple valid solutions are not unresolved interpretation. Keep real ambiguity
visible. Reuse the native API instead of guessing operator names or weaker
encodings. HIR uses `{"var":"x"}`, not `op:"var"`.

## 3. Construct, link and repair

Use exact quotation anchors such as `"span":{"quote":"Minimize total cost."}`;
scripts compute half-open Unicode offsets. Repeated quotes require zero-based
`occurrence`. Do not hand-count locations or fuzzy-match changed source text.
Location validity alone does not establish semantic correctness.

HIR macros expand only in expression positions. Makespan is an exact maximum,
not an auxiliary upper bound that is only tight under minimization. Hybrid terms
must be single Boolean expressions, without declarations, commands or objectives.
The full composition is parsed and type-checked using its shared declarations.

Compile with the fixed generator, then repair from source, context and actual
construction diagnostics. Retrieve missing rules when needed; keep every clause
and prior attempt. Selection, lookups, candidates and repair calls share the
caller's budget. Never send gold models, labels, optima or semantic-checker
counterexamples into held-out generation or repair.

## 4. Emit one stable response

```sh
python scripts/ir2smt.py model.json --source problem.txt --route hir --dialect z3 --mode full
```

Use `smtlib2` or `hybrid` for the other routes. Dialects are `z3`, `optimathsat`,
`smtlib-pure`, subject to installed backend capabilities. Unsupported optimization
is an error, never silently changed to satisfiability. The generator owns naming,
typing, lowering and command ordering; do not invent logic names or options.

Full mode emits JSON: `status`, `ir`, `code`, `assumptions`, `ambiguities`,
`diagnostics`, `meta`. Code mode emits raw SMT; IR mode emits JSON. Errors contain
no solver code. Preserve hashes, route, dialect, query polarity and
`solver_executed=false`. See [output contract](references/output-contract.md) and
[API](references/api.md) only for integration details. Translation is not proof
of NL correctness, satisfiability or optimality; the caller owns execution.

## Development and evaluation

[Examples](references/examples.md) provide one complete problem in three routes.
[Validation](references/validation.md) describes developer-side solver checks;
never execute them merely to fulfill a production translation request.

[Evaluation](references/evaluation.md) specifies same-source comparisons between
routes, model sizes, compact/full one-shot prompts and progressive retrieval.
Count all selection/lookup/repair tokens and calls, including failures. Resource
selection must never depend on reference answers. `skill_bundle.py` remains an
explicit static baseline. Progressive retrieval is implemented; its accuracy and
cost advantages must be measured rather than assumed.
