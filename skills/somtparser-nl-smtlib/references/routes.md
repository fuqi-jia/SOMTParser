# Three translation routes, one output contract

All routes consume the exact source and caller-owned context and produce
SMT/OMT text without executing a solver. The selected route is recorded and never
silently changed. Native SOMTParser may internally lower either route through
HIR; the experiment's distinction is the representation generated by the LLM.

## HIR

The model supplies typed HIR JSON. Obtain the live schema and constructor catalog:

```sh
python scripts/ir2smt.py --source problem.txt --route hir --request
python scripts/ir2smt.py model.json --source problem.txt --route hir --dialect z3
```

Use declared variables, exact literals, native operators, finite folds and CP
globals. The compiler resolves symbols, checks sorts, lowers globals and emits
the chosen dialect. Do not embed raw SMT strings in HIR expression fields.
Read [macro-library.md](macro-library.md) for the shared semantic patterns.

## Direct SMT-LIB

The model supplies `somt-nl-formal-v1` with a complete SMT program and source
links. The public parser/export path checks that selected interpretation:

```sh
python scripts/ir2smt.py --source problem.txt --route smtlib2 --request
python scripts/ir2smt.py model.json --source problem.txt --route smtlib2
```

This route tests the model's ability to write formal syntax and encodings. Its
closed-input contract prohibits includes and solver-option commands. Do not
promise dialect features the selected frontend refuses, even if the solver
itself supports them. The generator owns the final query/response envelope.

## Hybrid

The model supplies:

```json
{
  "schema": "somt-nl-hybrid-v1",
  "hir": {"...": "complete HIR model from the live schema"},
  "smt_constraints": [{"span": [0, 12], "term": "(>= x 0)"}]
}
```

HIR owns **all declarations, domains and objectives**. Extensions are single
Boolean SMT terms, not commands; no declarations, objectives, query commands or
options may be injected. Refer only to the HIR-emitted symbol interface and
lexically bound variables. Exact names must survive export; undeclared/renamed
symbols cause a diagnostic, never an inferred substitution.

The composer exports the HIR base, removes its query commands, adds the linked
assertions, and parses/type-checks/exports the complete combined model once.
Thus a scheduling global can stay in HIR while a specialized predicate is
written as SMT. An objective depending on such a predicate can use a HIR-declared
cost variable constrained by an exact SMT equality. Objectives have one owner;
there is no accidental second optimization problem in the extension.

The model's HIR assumptions/unresolved entries cover the whole hybrid problem.
Compilation is not intent validation. Empty SMT extensions are legal and must
be recorded as an HIR-only hybrid realization when analyzing route usage.

Hybrid does not bypass backend limitations: if either the HIR base or the final
combined frontend cannot represent a requested theory/priority, translation
fails explicitly. No hidden fallback to direct SMT or altered objective occurs.
